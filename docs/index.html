🧪 Red team: what happens when the AI gets it wrong

We fed the guardrails 13 deliberately bad proposals. Each was stopped or flagged.

Honest caveat: these results use the offline planner, which ignores the free-text request, so two request-driven scenarios pass trivially. Live Claude results are pending. See the model card for limitations.

🚨

Emergencies stop everything

“Ate chocolate”, “seizure”, “collapsed”: the planner never runs, and you're pointed to a vet and the ASPCA poison line.

📚

No source, no task

Every task must cite a retrieved excerpt from the vetted knowledge base. Missing or invented citations are blocked.

💊

Doses are the vet's job

Drug names, doses and home remedies are blocked in code, not just in the prompt. Prescriptions show up only as reminders.

🔁

It checks its own work

Each plan is dry-run on the real scheduler. Too long? Blocked tasks? The agent gets the feedback and tries again.

About the project

From a rule-based scheduler to an AI system you can audit.

WhiskerWise started as PawPal+, a Module 2 project: a Streamlit app where owners typed in every task and a priority-based scheduler fit them into the day. WhiskerWise keeps that scheduler as its engine and adds an AI layer that suggests the tasks, grounded in AVMA and veterinary-clinic guidance, with guardrails, human approval, logging and an evaluation harness.

Design choices

  • Local BM25, not embeddings. 30 chunks don't need a vector DB, and you can see why a chunk matched.
  • Rules in code, not just the prompt. A prompt is a request; a guardrail is a guarantee.
  • Works offline. No API key? A deterministic planner keeps everything runnable and testable.
